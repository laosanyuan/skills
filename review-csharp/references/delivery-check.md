# 主干交付与本机调试残留

主干不得包含只为某位开发者或某台机器服务的临时调试逻辑。检查指定待合入提交及其关联构建、配置、XAML 和启动入口；核实用户指定目标分支，不硬编码 main/master，也不把无关未提交草稿算成待合入内容。文件评审可以指出不符合该交付要求的内容，但没有目标基线时不宣称完成了分支合入审查。

## 追到实际依赖和进入路径

- 检查个人用户目录/绝对盘符路径、机器名/账户名分支、私人 IP/端口/本地服务、特定设备序列号、本机文件/程序集、临时启动参数，以及强制 mock/离线/测试账号、跳过鉴权或吞掉异常的排障代码。读取消费者和调用/配置来源，不以关键字命中直接判错；报告敏感值时只展示必要脱敏片段
- 包括项目文件、Directory.Build.props/targets、条件符号、配置默认值与回退、Content/CopyToOutput/发布项、资源 URI 和 XAML code-behind。说明在哪个源码/构建/运行层面违反交付约束，检查是否替换正式实现、污染默认配置或要求他人复制个人环境
- `#if DEBUG`、Debugger.IsAttached、设计时分支或一个环境变量开关不能自动豁免个人调试残留。即使 Release 不执行，确认是个人硬编码排障逻辑且仍随主干源码交付时，也应报告本次交付违规；同时明确受影响的配置，不虚构它必然造成 Release 故障
- 最小方向是移除临时个人逻辑，或在确有维护价值时改成明确、可复现、跨环境的正规诊断入口；个人取值留在不跟踪/不发布的本地配置中，不含真实凭据。改成另一个硬编码路径、默认仍回退私人地址或仅加条件符号，不算消除了依赖

## 排除误报

不能把所有 Debug/Trace、localhost、绝对路径、环境变量、设计时数据或测试替身一律禁止。需区分个人临时排障逻辑与有明确项目契约、可复现的开发/测试设施或正式诊断功能，例如仓库自带相对路径样本、框架隔离的设计时数据、团队明确支持的本地服务、正常平台目录 API 和不改变业务语义的日志。测试工程/正式诊断也不是天然豁免：若实际仍绑定个人机器，照样报告。

“主干不允许个人残留”是交付约束，不必捏造运行事故才能提出；项目确有特定部署环境要求则核实该契约，不能把正式部署约束误认作个人调试。关键事实不明时列待确认项，说明需核实的来源或支持环境。

按实际后果分级，并区分交付违规与可证实的功能/安全故障；同一根因不跨分类重复计数。给出位置、个人环境依赖证据、参与交付的路径与最小整改方向。不能仅凭 Debug 命中就宣称泄密或主干无法运行，也不自动删除文件、修改发布配置或批准合并。
