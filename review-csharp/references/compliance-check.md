# 格式评审边界

本包 [代码规范](代码规范.md) 是仓库中 format-csharp 同名规范的完整副本，便于独立安装。该副本只提供规则，评审权限和输出方式以 [review-csharp](../SKILL.md) 为准；原文的修改建议不授权本次执行修复。维护时同步两份文件，不单独改写一套相近但不同的规则。

该副本用于 C#，不是 XAML 格式标准。XAML 按项目的 `.editorconfig` 和 XML/XAML 约定检查；不要求 XML 添加 `/// <summary>`、C# region 或 C# 成员顺序。绑定、资源与标记扩展的语义问题按 [XAML 联动审查](xaml-review.md) 判断，不因 XML 解析成功就宣称正确。

## 判定顺序

1. 先按用户指定主题、文件或 diff 确定范围；用户只要功能问题时，不夹带格式报告
2. 用户明确选择、适用仓库指令及项目强约束优先；本包提供默认约定。读取相关 `.editorconfig`、生成器与已有绑定约束，不因默认 Tab、名称或 region 与项目不同就强行判错
3. 阅读规范并核实真实语法/声明及上下文；diff 评审不扩展清理无关历史代码，文件评审才按文件范围检查
4. 把确认为样式违规的内容与功能缺陷分开，按规则聚合并给具体行号。原始脚本候选须人工确认；缺注释/低可读性不自动升级成运行错误

## 注释重点

- summary 必须先准确，再简短：描述类/接口职责、方法目的、属性含义，默认一个简短内容行；根据真实实现和契约核实，不只翻译名称
- 开始标签与结束标签各占一个物理 `///` 行，正文放在中间；自然语言注释结尾省略中英文句号。实现原因留在相关逻辑附近，必要调用契约放 param/returns/exception/remarks，不为缩短摘要删掉契约或有效链接
- 保留版本、小数、URL、成员名、缩写、省略号和字面数据的点；有效 inheritdoc/include 可沿用。不要把 raw/verbatim 字符串、XML 示例或生成/法律文本中的形状当作应修改注释
- summary 是否过度不能按长度或关键词判定；例如“初始化任务”与“逐项启动设备并订阅通知”不在同一抽象层级。名称不准确时优先报告含义冲突，不为了让摘要成立建议改程序行为

## 命名与布局的边界

按规范核对命名、受控语句大括号、成员六组、region 及属性/backing field 单元。单成员组或仅一种组可省 region，不额外强制 Commands 组；字段和属性初始化顺序、条件编译、StructLayout、attribute 与文档附着关系不能为排版而改变。

风格更名建议必须说明已公开、持久化、生成或绑定名称的兼容性；不要建议直接全局替换。浮点比较、匿名委托、StringBuilder 和枚举文本是需要语义判断的审查信号，不是格式禁令。

## 可选工具

本技能不依赖 format-csharp 的安装目录或脚本。没有配套工具时按本包规则人工审查，不声称运行了检查器，也不为取得脚本自动安装其他技能。

当前环境确实提供 format-csharp，且需要机器定位时，可按其真实技能根目录加载相应说明并使用只读候选检查；不要在本包拼出不存在的 scripts 路径或硬编码用户目录。文本检查只提供候选；可选 Roslyn 只检查真实文档 summary 布局与句末句号候选，不判断摘要职责、缩写或完整 XML 渲染语义。

这些脚本不评估 MSBuild，不能直接拿工程/解决方案当目录范围；先核实文件集。执行状态、候选命中和合规结论分别处理；解析错误、inactive 分支、空范围或工具失败不是零问题。需要构建工具副本时另核对获准产物位置和副作用，不因此修改受审源码。
