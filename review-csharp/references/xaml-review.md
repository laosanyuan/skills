# XAML 与 C# 联动审查

涉及 XAML 变更，或 C# 改动影响其绑定、事件、资源和生成成员时使用。先从项目文件、包引用和根命名空间确认框架及版本（WPF、WinUI/UWP、MAUI、Avalonia 等），不把其中一个框架的属性、默认绑定模式或生命周期当作所有 XAML 的规则。

## 确定实际参与运行的文件

- 核对 `.xaml`、`.xaml.cs`、`x:Class`、partial、生成成员和构建项；按框架核实 Page/ApplicationDefinition/MauiXaml/AvaloniaResource 等、链接文件、资源 URI 与发布条件。不将目录中的全部标记当作已加载界面，也不因 `.g.cs` 未检入就认为缺少生成代码
- 从实际视图创建/导航/启动入口追到 code-behind、ViewModel、合并字典、Style/Template、转换器与命令实现。只读文件不足以覆盖运行链时说明缺口，不擅自启动设计器或构建受审工程来补证据

## 绑定必须追到真实来源

- 每个候选先确定绑定源：显式 Source、ElementName、RelativeSource、继承的 DataContext/BindingContext 或框架的编译绑定机制。DataTemplate 通常切换到数据项上下文，模板/弹出层及名称作用域需按实际框架核实；不能把所有绑定都解释成窗口 ViewModel 的成员
- 从有效源类型检查路径、大小写、嵌套对象、属性可访问性、命令参数及转换类型。读取 DI/导航赋值、构造函数、资源和外部上下文契约；设计时 `d:DataContext` 或类似数据本身不证明运行时来源，外部来源缺失时不据此断言成员不存在
- 核对 Binding/x:Bind/编译绑定的默认模式及更新时机，目标属性的默认元数据、Mode、UpdateSourceTrigger、INotifyPropertyChanged/集合通知/框架属性机制。仅报告实际会变化且必须更新的路径；初始常量、OneTime 或其他已生效通知机制不机械要求额外通知
- 输入到保存/命令执行要核对数据何时回写、校验和转换是否生效、命令参数是否属于预期对象。不能因写了 TwoWay 就认为用户最新输入一定已提交，也不把所有绑定失败说成编译错误；明确是编译诊断、加载异常还是运行时失效

## 资源、模板与生命周期

- 核对资源键与实际查找范围、字典合并顺序、URI/程序集/Build Action，以及 StaticResource/DynamicResource 或对应框架机制。检查隐式样式、TargetType、BasedOn、主题和模板覆盖是否造成可证实的丢失或类型不兼容；搜不到同文件定义不等于资源不存在
- 联合 XAML 事件声明、行为/触发器与 code-behind 检查重复挂接、Loaded/Unloaded 或导航反复进入、发布者与视图寿命、解绑及在途回调。XAML 声明事件本身不是泄漏；需要证实重复路径或实际保留链
- 布局/交互问题需有窗口约束、支持尺寸/DPI、可达状态或交互证据。检查裁切、重叠、焦点/键盘、可见性与命中测试的实际影响，不凭固定尺寸、某个 Panel 或未运行的视觉猜测断言界面不可用
- 大段复制的控件结构、Style/Template 及重复事件逻辑按行为审查中的复用边界判断；抽取建议要保留资源查找、名称作用域、绑定源、事件路由及不同视图的真实差异

## 交付证据

问题定位到最小 XAML 属性/标记及必要的 C# 或资源来源，并说明触发操作、解析/更新路径、后果和最小方向。缺少运行时上下文或资源装配证据时列待确认项。静态阅读、XML 语法检查、框架构建、真实绑定诊断与视觉交互验证各证明不同事情，不能互相冒充；未运行界面就不声称已验证显示或点击效果。
