# C# 默认代码规范

本文件提供 format-csharp 的默认约定，不覆盖用户明确选择或适用仓库指令。与项目既有约束冲突时记录差异；只做格式整理不能借规范之名修改运行行为。脚本仅辅助定位，判断与修复方式见 [检查指南](compliance-check.md)。

新增规则时同步相关说明；能够可靠脚本化的增加候选规则与行为测试，否则标为阅读判断。规则的执行范围以本次任务为限，不能因局部修改强制清理整个仓库。

## 命名与基本格式

| 标识符 | 默认规则 | 示例 |
|---|---|---|
| 命名空间、类型、方法、属性、事件、枚举值 | PascalCase | `DeviceService`、`StartServices`、`Changed` |
| 接口 | I + PascalCase | `IDeviceService` |
| 自定义特性、异常 | Attribute / Exception 后缀 | `AuthorAttribute`、`DeviceException` |
| 私有字段（含 static、readonly） | _camelCase | `_device`、`_defaultTimeout` |
| 非私有字段 | PascalCase | `FieldName` |
| 常量（const，不含 readonly） | PascalCase | `MaxValue` |
| 参数、局部变量 | camelCase | `bootstrap`、`deviceCount` |
| 绑定命令属性 | Command 后缀，不用 Cmd | `UseCommand`、`PrevCommand` |
| 测试类 | 被测类型 + Tests，必要时加关注点 | `DeviceManagerTests`、`GameAudioProviderUpdateAudiosTests` |

- 标识符使用英文，不用中文；字符串、注释和断言提示可使用中文。测试方法可用 `Method_WhenCondition_ThenResult` 等项目既有风格，不把场景全部塞进类名
- 命名表达实际职责或领域含义。方法通常用动宾、谓词或转换短语，变量不使用无语义的占位名；循环索引、坐标和数学公式中的短名可有明确意义
- 避免仅靠大小写区别、缩写含混或与现有符号冲突的名字。已公开/持久化/生成的标识符要先检查契约，不机械改名
- 已经表示相反动作的一对命名保持一致，如 Start/Stop、Open/Close、Subscribe/Unsubscribe；不要求凭空补齐另一半函数
- 默认 Tab 缩进；若项目明确采用 space，按用户/项目规则处理，冲突先说明。大括号采用项目约定，整理不擅改 `.editorconfig` 或换行配置

## 注释规范

### 声明文档的内容

类、接口、属性、方法和函数的声明文档只简短描述“是什么 / 做什么 / 表示什么”，与声明保持同一抽象层级。类和接口写核心职责，方法写目的或结果，属性写值或状态，默认一个简短内容行。

名称已清楚时，直接写对应的简短中文短语，不为了增加信息量展开内部步骤、协作者、调用顺序、订阅方式、后台/线程策略、回滚恢复过程或资源释放细节。只改变实现而职责不变时，summary 应仍然成立。

名称只是线索，不能直接把误导性名称翻译成结论。先核对真实返回值、状态含义及失败路径，例如操作失败也会增加的计数不是成功次数；summary 只写核实后的简短含义，不展开内部步骤，也不为使注释成立而修改原行为。

| 声明 | 合理的 summary | 不合理的展开 |
|---|---|---|
| `DeviceServiceManager` | 管理设备服务 | 枚举该类依赖的设备、插件及调用流程 |
| `StartServices` | 开启服务 | 接入设备状态通知，并在后台启动设备和插件初始化 |
| `InitializeAsync` | 异步初始化 | 展开每一步初始化顺序 |
| `ClearServices` | 清理服务 | 取消插件更新并释放游戏服务 |
| `InitializationTask` | 初始化任务 | 游戏加载等待启动同步结束；不阻塞窗口和设备服务 |

调用者必知的参数约束、返回值、异常、副作用及补充契约按性质写进 `<param>`、`<returns>`、`<exception>`、`<remarks>`，不要为缩短 summary 删除这些契约。只记录实际确认的行为；参数名、泛型名与签名对应，void 不写虚构返回值，Task 的返回说明区分任务与完成结果。

### 标签布局与标点

`<summary>` 与 `</summary>` **各独占一个物理 `///` 行**，内容放在中间，即使只有一句也不豁免。其他 XML 标签内容短时允许单行。标签使用正确的小写 XML 名，不写 `<Summary>` / `<Param>` 代替标准标签。

所有 C# 自然语言注释结尾省略中文句号 `。` 和英文句末句号 `.`，包含 XML 文档、普通/行尾 `//`、块注释及 XML 结束标签前的正文。版本号、小数、URL、文件名、成员名、缩写和省略号中的点保持不变；不要改动必须原样保留的工具指令、法律文本或字面数据。

```csharp
/// <summary>
/// 开启服务
/// </summary>
/// <param name="bootstrap">设备引导程序</param>
// 回滚目录切换
```

以下形式不合规：

```csharp
/// <summary>开启服务</summary>
/// 开启服务。
/// <param name="bootstrap">设备引导程序.</param>
// 回滚目录切换。
```

### 覆盖与普通注释

- 类、接口、属性和方法/函数提供职责文档，不只 public；已有可解析的 `<inheritdoc/>` 或 `<include>` 可沿用，核对继承/引用目标，不重复生成同样内容
- 事件不强制头部 summary；事件处理方法仍按方法规则。构造函数按需要说明初始化职责及不显然的参数约束，不生成冗余的析构说明
- 参数、返回值和异常说明以调用契约需要为准，不为了填标签复述类型或编造范围。保留项目明确要求的完整文档覆盖
- 复杂逻辑中必要且不显然的原因、边界、不变量或兼容性处理写在对应代码附近；不机械搬运删下来的每条实现细节，代码已经清楚表达的内容无需复述
- 普通行注释通常放相关逻辑前，与代码缩进对齐，`//` 后空一格。更新失效注释；不以“解释了为什么”为由删除有价值的设计理由
- 文件头“作者/日期/修改记录”属于默认跳过的遗留模板，只有用户明确要求才补，且不编造作者和日期。保留必要版权和许可证头

## 表达式与语句

1. if、else、else if、for、foreach、while、do 的受控语句用 `{ }`，即使是 return/throw/break/continue/yield 也不豁免；控制头和执行语句分行。else if 链无需额外嵌套成 else 包 if，do-while 的尾部条件不另加代码块
2. 运算优先级不直观时加括号明确分组，但不改变求值顺序、短路逻辑或副作用。不为每个简单算术表达式叠加括号
3. 复杂复合表达式、循环内修改控制变量和长字符串构建需要阅读判断；提取变量、拆分逻辑或性能优化若超出格式范围，先列建议

### 需语义评估的写法建议

下列是审查信号，不是可自动修复的格式禁令：

- 浮点直接相等比较：确认是否需要近似相等、业务尺度及 NaN/Infinity/哨兵行为。不得自动换成任意 epsilon，`float.Epsilon` 不是通用容差
- 匿名 delegate：是否提取具名方法取决于可读性、闭包和事件解绑需求，不能忽略捕获和委托身份
- 循环中字符串拼接：需要优化时保留求值顺序、null、格式化与中间状态，先证实工作量/瓶颈，再考虑 StringBuilder
- 枚举 `ToString()`：日志或调试可用；外部协议/持久化标识不能盲目依赖可重命名的枚举成员文本。是否需要显式映射或现有注解由契约决定，不一律加 Description；混淆是否改名取决于实际混淆配置，不宣称必然失败

格式任务只报告这些语义/结构/性能建议。用户明确授权相应调整后，另外验证兼容性与行为，构建通过不等于等价。

## 代码布局

### 六组默认顺序

1. 字段（含 const / static / readonly；对应 region 名沿用 `[Private Fields]`，非私有字段若存在也在字段组）
2. 属性（所有访问级别，含命令属性）
3. 事件
4. 构造函数（含静态构造、析构）
5. 公有方法（含 internal）
6. 私有方法（含 protected）

固定 region 名依次为 `[Private Fields]`、`[Properties]`、`[Events]`、`[Constructors]`、`[Public Methods]`、`[Private Methods]`。`[RelayCommand]` 不改变方法分组；不强制生成第七个 Commands 组。嵌套类型按项目风格保持完整，不用未覆盖的类别强行套六组。

### region 与间隔

- 多个非空组并存时，含两个及以上布局单元的组用对应 `#region` / `#endregion` 包裹
- 单成员组，或整个类型只有一种非空组，可以省略 region；已有 region 也允许，不报告“单成员 region 必须删除”
- 不同 region 之间空一行；相邻方法、属性单元之间空一行，不以某方法内部已有空行为分隔合格的证据。字段之间不强制空行
- 有关联的重载/调用方法尽量相邻；已有必要子 region 可以保留，但不能跨越/破坏成员归属或预处理结构

### 属性与 backing field

建议将已确认的 backing field 放在对应属性前，作为 Properties 中的一个布局单元；保留安全且一致的既有放法，不只凭同名推断并移动字段。源码生成属性需先检查生成规则，不把推测生成的成员计作额外源码声明。

```csharp
#region [Properties]

private int _count;
public int Count
{
    get { return _count; }
    set { _count = value; }
}

private string _name;
public string Name
{
    get { return _name; }
    set { _name = value; }
}

#endregion
```

field + 对应 property 计一个单元，不要求其内部空行；两对之间仍留空行，不能因为组中有 backing field 就豁免整个 region 或所有间隔。

### 重排的安全边界

成员的 summary、attribute、条件编译块必须保持附着关系。保留字段与自动属性初始化器的相对执行顺序，检查 StructLayout/互操作/反射和源生成器依赖。不能为成员顺序好看而改变这些契约；必要时只补 region/空行，并报告无法安全重排的部分。
