# 行为验证可靠性

用于自建 / 修改行为测试、旧新实现差分探针，或排查可疑的测试成功。成熟且覆盖本次修改的现有测试可直接复用，不要求每次重构都重建测试框架或做完整变异测试。

## 先证明测试装置有效

- 核实实际加载的目标路径和改前基线，避免两端加载同一份修改后代码。基线包含用户原有修改；脏工作区不能直接用 `HEAD` 代替改前状态
- 在做差分比较前，让两端各自通过有具体预期的有效输入：断言返回值，以及与改动有关的状态或回调次数 / 顺序。异常路径则断言预期异常及抛出阶段；参数绑定、导入或夹具错误不能当作预期业务失败
- 证据应来自被测逻辑，例如目标回调、状态变化或实际函数体覆盖记录；调用前包装器里的计数只能证明尝试调用。`await` 异步调用，并按待验证契约消费迭代器，不能仅比较协程 / 生成器对象
- 对测试装置新写的关键断言做小范围反证：在授权隔离副本或可恢复测试替身中，故意破坏本次声称覆盖的一项行为，确认测试因对应断言而失败。恢复后重跑正常版本；仅因语法、导入或夹具失败不算检出目标缺陷。负向对照仍通过时，先修测试，不交付该通过结论

## 避免差分测试的共同假阳性

“旧输出等于新输出”只说明两次观测相同；若两端都未执行、都返回空值或都被同一个异常捕获器截断，比较仍可能通过。不要只比较异常类型 / 文本，或把所有异常转成相同的失败标记；为正常路径补具体成功预期，为失败路径补预期类型及必要的副作用证据。异常确属契约时可以捕获比较，但非预期异常必须使相应用例失败。

Python 特别注意：普通函数存为测试类属性后，经 `self.fn` 取出会绑定实例并隐式多传一个参数。保存为实例属性、明确使用 `staticmethod`，或通过模块 / 局部变量调用；需要验证真实实例方法时保留正常绑定。修改绑定后也要重跑预期断言，不能只看两端签名一致。

以下是自包含的最小测试装置示例，不是业务验收模板。实际任务应从原实现与调用契约提取预期，并按相关状态 / 时序扩展：

```python
import unittest


def calculate_total(values):
    return sum(values)


def assert_total_contract(case, calculate):
    case.assertEqual(calculate([2, 5]), 7)
    case.assertEqual(calculate([]), 0)
    with case.assertRaises(TypeError):
        calculate([None])


class TotalTests(unittest.TestCase):
    def setUp(self):
        self.calculate = calculate_total  # 实例属性保留普通函数的调用方式

    def test_contract(self):
        assert_total_contract(self, self.calculate)

    def test_detects_wrong_total(self):
        with self.assertRaises(AssertionError):
            assert_total_contract(self, lambda values: 0)


if __name__ == "__main__":
    unittest.main()
```

## 让交付结论与证据对应

- 核对命令退出状态、实际发现 / 执行的用例、失败与跳过。零用例、全部跳过、仅收集、超时或仅打印 `PASS` 都不能支持“行为测试通过”；部分跳过时只报告已有效执行的部分
- 测试方法、循环子场景与断言数不是同一口径。说明相关场景和已检查的返回 / 异常 / 状态 / 顺序即可，不为凑数量把循环次数当有效覆盖；不把装置的反证用例计为业务场景
- 保留验证命令、退出码及必要日志或断言位置，明确未覆盖项。独立复核通过不能追溯修复原先失效的自测声明；区分原验证无效与后续补验结果

已有证据足够且输入、源码、装置未变时停止追加同用途测试。以上检查提高测试可信度，不构成所有输入下的等价性证明，也不授予扩大写入范围、改全局环境或运行外部副作用的权限。
